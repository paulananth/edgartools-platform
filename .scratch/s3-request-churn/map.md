# S3 Request-Churn Elimination

Label: `wayfinder:map`

## Destination

Reduce production S3 `Requests-Tier1` spend by replacing measured broad listings
and repeated existence checks with run-manifest, exact-key, and bounded
prefix/batch access, while preserving immutable Bronze artifacts, loader
idempotency, and all existing data-publication contracts.

## Notes

- **This map carries execution.** The user has fixed the direction: attribute
  requests first, change request behavior second, and do not touch retention.
- Account and region: AWS account `690839588395`, production resources in
  `us-east-1`; re-verify identity before every live measurement or mutation.
- Accepted attribution standard: use one bounded production observation with
  application-level S3 operation counters and a deliberately small set of
  prefix-scoped request metrics; attribute at least 95% of Tier-1 requests by
  bucket, prefix, and operation before selecting optimizations.
- Baseline evidence: Cost Explorer reported 149,587 Tier-1 requests on
  2026-07-29, 549,889 on 2026-07-30, and 237,451 on 2026-07-31. No current
  bucket had S3 request metrics or server access logging, so the historical
  spike cannot be attributed exactly by prefix after the fact.
- Required implementation discipline: use `/gof-refactor-reviewer` before code
  changes, then `/tdd` and `/code-review`. Do not force a pattern.
- Bronze is additive and immutable. Existing artifacts, versions, checksums,
  conditional writes, conflict behavior, and default skip/idempotency semantics
  are hard invariants, not optimization levers.
- Prefer counters and metrics whose own cardinality and cost are bounded. Do
  not replace S3 request churn with unbounded CloudWatch custom-metric churn.

## Not yet specified

- Which concrete runtime call sites dominate the attributed requests. This
  becomes specifiable only after the production baseline binds request volume
  to bucket, prefix, operation, workflow, and run.
- Whether any material unattributed remainder is generated by AWS-managed
  consumers rather than the warehouse runtime. Graduate a separate ticket only
  if the accepted attribution leaves at least 5% unexplained.
- The exact reduction target beyond the 95% attribution gate. Set it from the
  measured avoidable-request denominator rather than inventing a percentage
  before the baseline exists.

## Out of scope

- Retention-policy changes, lifecycle expiration, storage-class transitions,
  deletion of current or noncurrent Bronze artifacts, and version cleanup.
- Weakening immutable-write conflict checks or switching idempotency from
  verified source/checkpoint state to optimistic assumptions.
- Replacing S3, migrating Silver to PostgreSQL, or redesigning the AWS data
  plane; this effort is limited to request access patterns.
