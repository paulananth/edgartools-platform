# R3: Provider access and captured files

Question: From a Snowpark Container Services (SPCS) service, which mechanism lets it fetch only named hosts? What stays latency-bound by the internet? Where do captured files live?

Method: Snowflake documentation only (WebSearch and WebFetch). No provider request, no account touched, nothing measured. Claims are "from the documentation" unless marked.

## Answer

**Named-host egress (confidence high, from the documentation).**
- Service containers have no internet access by default.
- An egress network rule (`CREATE NETWORK RULE`, `MODE = EGRESS`, `TYPE = HOST_PORT`) lists full host names in `VALUE_LIST`; wildcards are not supported.
- SPCS accepts only ports 22, 80, 443 and 1024+.
- An account administrator bundles the rules into an external access integration (EAI, `ALLOWED_NETWORK_RULES`, egress rules only) and grants `USAGE` to developer roles.
- The service attaches it with `EXTERNAL_ACCESS_INTEGRATIONS` in `CREATE SERVICE` or `EXECUTE JOB SERVICE`. The owner role needs `USAGE` on the EAI and `READ` on each referenced secret.
- `ENABLED = FALSE` cuts reach to every location the EAI covers.
- So the allowlist for SEC, GLEIF and OpenFIGI is one egress rule per host, in one EAI (inference from the above).

**Secrets (confidence high, from the documentation).**
- A secret reaches a container as an environment variable (`envVarName`, fixed at creation) or as a file under `directoryPath` (updated in place).
- Only OAuth2 secrets must be allowed by the EAI, or service creation fails. Other secret types need no EAI allowance.
- `ALLOWED_AUTHENTICATION_SECRETS` is documented for UDF and procedure handlers. I did not find it for SPCS services (not found for SPCS).
- Whether the existing provider authorization needs a secret at all is not settled by the documentation. The research did not check provider terms.

**Latency (confidence medium-high, inference; not measured).**
- The documentation says services "can optionally communicate with the public internet" and gives no egress latency figures.
- PRIVATE_HOST_PORT (EGRESS) routes outbound traffic through a private connectivity endpoint the customer runs. SEC, GLEIF and OpenFIGI do not offer one, so each provider fetch still crosses the public internet.
- Provider fetches are internet-latency-bound. Calls between the service and Snowflake tables stay inside Snowflake.

**Captured files (confidence high, from the documentation).**
- Internal stage volume (`stageConfig`): optimized for large sequential reads and writes. Random writes, appends and external stages are not supported. Renames are not atomic. Captured SEC files are additive and immutable, so write-once per file fits.
- Block storage volume: 1Gi to 65536Gi on AWS, 1Gi to 16384Gi on Azure, 4Gi to 16384Gi on Google Cloud; 3 per service, 100 per account; size fixed after creation; survives upgrade and suspend/resume; deleted when the service is dropped; snapshot on delete defaults on for services. Block volumes with job services are a preview feature.
- Memory and node-local storage are not durable. Not for captured files.
- External stages are not mountable in SPCS volumes; copy into an internal stage first.
- The raw V1 stage syntax is deprecated and a 2026_08 bundle note says new V1 services are rejected by default; use `stageConfig` (from a search result, not fetched in full).

**Costs.** The stage-volume page has no billing text, only memory use (512 MB per mounted stage). Block storage is billed while a service is suspended, and until a job is dropped. The stage storage charge was not found in the documentation.
