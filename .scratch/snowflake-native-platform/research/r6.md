# R6: AI native (Cortex), item 6

Question: which Cortex features (semantic views, Cortex Analyst, Cortex Search, Cortex Agents, MCP) read our gold and ontology in place, what is the agent interface beside today's agent contract, and what are the availability, region, edition and billing facts?

Method: Snowflake documentation only, read through WebFetch and WebSearch. No account touched, no provider request, no file edited except this one. Nothing was measured. Every claim below is "from the documentation" unless marked as an assessment.

## Answer

**Gold in place: semantic views.** Cortex Analyst reads semantic views, and the legacy YAML-on-stage model is kept only for compatibility; semantic views are the recommended form (from the documentation, cortex-analyst page). The MCP server supports only semantic views with Cortex Analyst, not semantic models (from the documentation, cortex-agents-mcp page). Semantic views hold relationships (joins on shared keys), dimensions, metrics and facts (from the documentation, views-semantic overview). Confidence high.

**Ontology.** Semantic views are the nearest Snowflake object to AutoOntology. They cover terms (dimensions, metrics), and joins on shared keys. The overview page does not mention typed relations such as "issued by" or "held by", synonyms or verified queries (from the documentation). Assessment, confidence medium: they cover terms and joins, not typed relations, so typed relations must stay in our `rules/context` definitions or a table we own. I did not find a page called "business ontology" in these fetches; I did not verify its existence.

**Availability.**
- Semantic views: the overview page states no GA or preview status. A release note dated 2025-04-17 labels them preview (search result, not fetched in full). Best-supported answer: generally available, confidence medium; confirm the status in the release notes before a design depends on it.
- Cortex Analyst: no status stated on its page.
- Cortex Agents: no overall status stated. Only "Analytical search" is labelled Public Preview. The REST call is `agent:run` (from the documentation).
- Snowflake-managed MCP server: generally available since 2025-11-04 (release-note title, from search result). Not available in Azure US Gov Virginia (non-FedRAMP High); formal FedRAMP assessment not complete (from the documentation).
- Cortex Search: some sub-features are labelled preview (auto-suspend option, stage data source). Core status not stated.

**Regions.** Cortex Analyst is native in AWS ap-northeast-1, ap-southeast-2, us-east-1, US East (Commercial Gov, N. Virginia), us-west-2, eu-central-1, eu-west-1, and Azure East US 2 and West Europe. Elsewhere it uses cross-region inference (from the documentation). Cortex Search is listed by region, and some regions are cross-region only (from the documentation). Our account's region is not known to this research; it is not asked, per the ticket.

**Edition.** None of these pages states a required edition (from the documentation). Confidence medium that no edition gate exists; confirm on the account.

**Limits.** Cortex Search: 20 QPS per search service, 140 QPS per account, source under 400M rows, source queries must follow Dynamic Table restrictions (from the documentation). MCP server: 50 tools per server, excluding tools generated from tool_config (from the documentation); SYSTEM_EXECUTE_SQL defaults to read-only and should not share a server with a governed agent (from the documentation).

**Billing units.**
- Cortex Analyst, standalone: per 1,000 successful messages. The rate is not on the page, and the feature table calls it "Platform Credit (legacy)", which conflicts with the text (from the documentation).
- Cortex Analyst inside Cortex Agents, and Cortex Agents: AI Credits per million tokens processed, rate depends on the model (from the documentation).
- AI Credit: $2.00 with global routing, $2.20 with regional routing; Cortex Search is always billed at $2.20 (from the documentation; no effective date stated).
- Cortex Search: serving in credits per GB per month of uncompressed indexed data, while the service is available; embedding per token on insert or update; batch per GB per hour; no warehouse credits when a refresh finds no change (from the documentation). Rates not on the page.
- Generated SQL: standard warehouse credits (from the documentation).
- Semantic views: "considered metadata"; no billing stated. MCP server: no billing terms on its page; the work its tools trigger is billed.

**Agent interface beside today's contract.** The contract in `docs/specs/agent-context/spec.md` (this worktree; read only) is deliberately no MCP, no new service, no embeddings. Agents read Postgres views (`mdm.entity_context`, `mdm.relationship_context`, `rdm.code_context`, `silver.table_context`) through the `edgar-warehouse context` command, read-only, answers at most 8 KB. Proposal, assessment, confidence medium:
1. Keep that contract as the one agent interface on every platform.
2. Inside Snowflake, add a semantic view over gold for Cortex Analyst questions. Its join keys and metrics mirror the same identifiers.
3. Add a Cortex Agent with three tools: Cortex Analyst on the semantic view; Cortex Search only if the contract's logged search misses prove a need (the contract defers embeddings for this reason, and Search adds serving and embedding charges); and the context command as a custom tool (a stored procedure or UDF), since the views live in Postgres.
4. Expose the agent through an MCP server with no SQL execution tool, or through the `agent:run` REST API.
