# Legacy control retirement: local qualification

This branch is stacked on `codex/fresh-change-journal` (#738). It removes fresh provisioning and runnable access to the original Bookkeeping and Change Ledger control tables. The fresh owners are `bookkeeping_clean`, `rules`, and `change_journal_clean`. No AWS deployment or live database change was made.

The original Bookkeeping tables were `stg_daily_index_filing`, `sec_daily_index_checkpoint`, `discovery_checkpoint`, `pipeline_run_lease`, `sec_parse_run`, `sec_sync_run`, `pipeline_run`, `gold_manifest`, `sec_source_checkpoint`, and `sec_company_sync_state`. The original Change Ledger tables were `source_observation_cursor`, `source_fetch_decision`, `source_fetch_work`, `source_fetch_transition`, `source_revision`, `source_processing_decision`, `source_expected_producer`, `source_registry_version`, `source_registry_coverage`, `source_evidence_conflict`, and `source_evidence_import`; the two retired event mirrors were `bookkeeping_mirror.event` and `mdm_mirror.event`. Replacement owners and invariants are mapped in [the existing legacy inventory](../change-journal/LEGACY-INVENTORY.md).

On the disposable local `edgartools-clean-mdm-pg16` container, `bookkeeping`, `change_ledger`, and a second legacy Bookkeeping copy named `bookkeeping_cm05` were backed up with `pg_dump -Fc`, verified with `pg_restore --list`, then dropped. Their SHA-256 digests are `e462295be22fd00b19c02315199d94311b9567cfb643c1b83fa0c1d56ab11540`, `83e90c2bb70401f26b5c35c35f53af3bba99ccf9b95f87c4237e32d7bf9f738f`, and `550e3365eea426b40281c4a4460694496c5cfb6f7b5d8dae40ecf0cdb30d18cb`, respectively. The dumps are outside the repository under `/Users/aneenaananth/.codex/runtime/legacy-control-retirement-20260927/` with owner-only permissions. A subsequent database listing showed none of the retired databases; `bookkeeping_clean`, `rules`, and `mdm` remained. The separate fresh local container was not changed.

The removed SQL files, provisioning scripts, registry bootstrap and related tests no longer recreate those tables. The original connection factories now reject all calls, including explicit URLs. The standalone warehouse and affected MDM commands fail closed; the retired Change Ledger privilege monitor was removed. New task definitions no longer receive `BOOKKEEPING_DATABASE_URL`, the deploy script emits no legacy Step Functions registrations, and legacy schedule/alarm configuration flags fail before AWS access. The unused AWS legacy secret is detached from future Terraform state with `destroy = false`, preserving it as an archive on a later apply. Existing deployed AWS task definitions, state machines, schedules, databases, secrets and data are untouched.

Legacy ORM classes and historical restore SQL remain in source for archive interpretation; they are not applied by fresh migration or reachable through the application connection factories. The removed tests had created those tables directly or exercised retired control paths. This includes the four-company SEC/GLEIF scenario, whose old capture fixture depended on the retired ledger; its multi-company behavior is not yet requalified on the fresh route. Fresh PostgreSQL acceptance covers leased Bookkeeping work, Rules authority, Change Journal delivery/recovery and bounded configured acquisition/MDM. Feed promotion is deliberately disabled pending an exact approved Rules version and verified source-owned baseline manifest. The installer retains only Clean MDM connectivity and migration in place of the old registry bootstrap/standalone MDM work stage.

The Snowflake MDM analytics mirror is a separate serving surface and was not retired with the PostgreSQL `mdm_mirror.event` delivery table.

Local qualification: 280 PostgreSQL integration tests and 366 architecture tests passed without skips; unit tests passed 1,451 with eight optional skips, and MDM tests passed 1,129 with one optional skip. The retired schedule flag was checked against a fake AWS executable and made no AWS call. Shell syntax, Terraform formatting, focused Python F-rule lint, and the staged diff check passed. The required GoF review found no pattern refactor justified by this retirement.
